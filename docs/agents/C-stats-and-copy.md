# 担当 C: 公開の実績ページ `/stats` と、サイトの看板の言い換え

ブランチ: `feat/stats-and-copy` ／ worktree: `../Solana-idea-c` ／ DB の移行: 作らない

## なぜやるか
審査員は数字を見る。実際に何件の依頼が人の手で完了し、いくら Solana で支払われたかを、誰でも確かめられる形で見せる。X の投稿にもこのページを使う。あわせて、サイトの看板を今日決めた方針「人の作業の結果を、依頼した AI が信用できる形で返す」にそろえる。

## 作るもの
1. **実績ページ** `apps/web/app/(site)/stats/page.tsx`（サーバー側で描く。既存の `(site)` のページの部品と見た目に合わせる）と、同じ数字を返す `GET /v1/public/stats`（認証なし、60秒ほどキャッシュ）。
2. **出す数字**（DB から。個人の情報は出さない）
   - 完了した依頼の数（VERIFIED と SETTLED）、依頼の総数
   - 有効な提出をしたことのある worker の数、依頼者の数
   - worker に払った USDC の合計（確定した支払い）
   - 依頼から結果が出るまでの時間の中央値
   - AI による内容の確認の内訳（合格／差し戻し／判断できず）。`evidence_checks` の `vision_consistency` から
   - 依頼の種類ごとの件数
   - 直近14日の、日ごとの完了件数（素の SVG か CSS の棒グラフ。グラフのライブラリは足さない）
   - 直近10件の確定した結果: 既存の公開結果ページ `/r/<id>` と Solana Explorer へのリンクだけ。**依頼文・答え・写真・位置は出さない**（`specs/proofmarket/privacy-security.md`）
3. **導線**: サイトのヘッダーかフッターに `/stats` へのリンク。トップページに「実績」の小さな節（大きな数字を3つ）。
4. **看板の言い換え**: トップ（`app/(site)/page.tsx`）、仕組み（`how-it-works`）、開発者向け（`developers`）の見出しと冒頭の説明を、次の方針にそろえる。
   - 一言でいうと: AI が自分ではできない現地の確認や、紙の資料・実物・電話などの作業を人に頼み、その結果を **AI が中身まで確かめたうえで** 受け取れる。結果と支払いは Solana に残り、あとから誰でも確かめられる。
   - 差のつく点: 提出ごとの AI による内容の確認、複数人の合意、Solana に残る結果の記録とエスクローでの支払い。
   - 担当 A が作る x402（登録なしで依頼できる）は、A の PR が入ってから触れる。先に書く場合は「近日」と書かない。A の取り込みを待つ。
   - 「革新的」「民主化」などの中身のない言葉は使わない（`docs/colosseum-hackathon-playbook-2026-09-16.md` の Red Flag Word List）。
   - 開発者向けページの x402 の節は担当 A が書く。担当 E が接続手順の節を足す。その2か所には触らない。
