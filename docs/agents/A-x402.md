# 担当 A: x402 で「登録なしで、どの AI からでも依頼できる」ようにする

ブランチ: `feat/x402` ／ worktree: `../Solana-idea-a` ／ DB の移行番号: 0019（必要なときだけ）

## なぜやるか
いまは API キーを運営者が手で発行しないと依頼できない。x402 を入れると、AI エージェントは自分の Solana ウォレットから USDC を払うだけで、契約も登録もなしに依頼を出せる。審査で「ほかの AI にも搭載できるか」に答える決め手で、Solana を使う理由もはっきりする。Colosseum では AI 向けの支払いの仕組み（Latinum・MCPay・Corbits）が続けて入賞している。

## 作るもの
1. **x402 の窓口** `POST /v1/x402/verifications`
   - 本文は `POST /v1/verifications` と同じ。ただし `principal_ref` は不要。
   - 支払いが無ければ HTTP 402 と支払い条件を返す。金額は `bounty.amount × required_witnesses`（USDC の最小単位）。
   - 支払いが付いていれば、それを検証して Solana に送り、確定を待ってから依頼を作る。レスポンスは通常の作成と同じ形に、次を足す。
     - その支払い元ウォレット用の API キー（結果を `GET /v1/verifications/{id}` で読むため）
     - 支払いの取引の署名と Explorer の URL
   - 支払い元ウォレットごとに principal を1つ作る（表示名は `x402:<pubkey の先頭>`）。2回目以降は同じ principal を使う。API キーは毎回新しく発行してよい（秘密は一度しか返せないため）。
   - 受け取った額は台帳に TOPUP として入れ、そこから通常どおり RESERVE する。つまり `createVerification` をそのまま使う。
   - 冪等性: 同じ支払い（取引の署名）で2つ依頼が作られないようにする。
2. **支払いの検証と送信（自前の facilitator）**
   - 仕様は coinbase/x402 の最新版に合わせる。Solana の "exact" 方式: https://github.com/coinbase/x402/blob/main/specs/schemes/exact/scheme_exact_svm.md 。ヘッダー名（v1 の `X-PAYMENT` / `X-PAYMENT-RESPONSE`、v2 の名前）は、同じリポジトリの仕様書で確かめてから決める。公式の npm パッケージが Solana の検証を提供していれば使ってよい。無ければ自前で書く。
   - 検証すること（仕様の MUST をすべて）: 命令の並び（Compute Budget 2つ＋TransferChecked、任意で Memo）、手数料の支払者が転送の元や権限者になっていないこと、Compute Unit の単価の上限、転送先が `payTo` の ATA であること、金額が完全に一致すること、mint が `BOUNTY_MINT` であること。
   - `payTo` は運営者のウォレット（エスクローの資金元 treasury の持ち主。`packages/solana/src/anchor-adapter.ts` を参照）。手数料の支払者（`extra.feePayer`）も運営者の鍵にする。
   - ネットワークは Solana Devnet（CAIP-2 の識別子は仕様に合わせる）。本番では `SOLANA_EXPECTED_GENESIS_HASH` を確かめる既存の仕組みに乗せる。
3. **払って依頼する見本のエージェント** `scripts/x402-agent.ts`
   - 自分の Devnet ウォレット（鍵は `~/.config/proofmarket/x402-agent.json`。無ければ作る）で、402 を受け取り、支払いの取引を組んで部分署名し、再送して依頼を作り、結果が出るまで待って表示する。
   - ウォレットへの試験用 USDC の入れ方を README か指示の末尾に書く（Circle の faucet、または運営者の treasury から少額を送るスクリプト）。
4. **MCP からも使えるように**（時間が余れば）: MCP の道具の説明に x402 の窓口を案内する一文を足す。MCP 自体の支払い対応はしない。
5. **サイトの開発者向けページ**（`apps/web/app/(site)/developers/page.tsx`）に「登録なしで使う（x402）」の節を足す。curl 相当の流れと、見本のエージェントの使い方。
6. **仕様書**: `specs/proofmarket/implementation/ja/01-requirements-definition.md` に「4.19 x402 での依頼（2026-10-04）」を足す。05 章（API 設計）にも窓口を足す。

## 触らないもの
- 既存の API キーでの依頼の流れ（`POST /v1/verifications`）は変えない。
- 本番の環境変数・DB・Vercel。テストは PGlite と偽のチェーンで行う。

## 完了の条件
- テスト: 支払い無し→402 と正しい条件／正しい支払い→依頼が作られ API キーが返る／金額違い・宛先違い・mint 違い・手数料支払者の悪用・同じ支払いの再利用→すべて拒否。取引の送信部分は偽のチェーン（`test/support/chain.ts` に倣う）で置き換える。
- 手元の Devnet で、見本のエージェントが実際に払って依頼を作れたこと（ローカルの `pnpm dev:local` では偽のチェーンになるので、Devnet の実取引はオーナーの最初の画面で本番反映後に確かめる、と報告に書けばよい）。
- README の「仕上げ」を満たして PR を取り込む。
