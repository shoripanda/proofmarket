# Work log: 2026-10-09 (afternoon → evening)

What changed after the tick incident was closed, in the order it happened. Each item names its PR; this file only records the why and the result.

## No cap on the bounty (PR #14)

The owner asked for agents to be able to pay workers without a ceiling. The per-request (`TASK_AMOUNT_LIMIT_EXCEEDED`) and daily (`DAILY_SPEND_LIMIT_EXCEEDED`) checks were removed from create, for API keys and x402 alike. The prepaid balance and the per-minute call limit remain. The key columns stay (no migration) but are no longer read for the decision; the console stops showing them, and the home, `/en`, `/developers` and terms copy say there is no cap. Tests now send a 900 USDC request and expect 201.

## Production hardening (PR #18, ledger note #19)

The 2026-10-08 audit named what to fix before real use. All of it that code can fix is in:

- **A time bomb in the tests.** `outbox_jobs.run_after` was left to the database default (`now()`), while the drain compares it with the app clock. The test clock is fixed at 2026-10-09T03:00Z; from the moment real time passed it, every new job in a test was "not due yet" and 14 unrelated tests failed on main. `enqueueJob` now takes the app clock. Ledger entry in `CLAUDE.md`.
- `tick` handles deadlines oldest first, at most 200 per run.
- The daily purge also drops rate-limit windows older than two days, idempotency keys past 24 h, and OAuth codes and tokens expired for a day.
- `GET /v1/health/ready` for an outside monitor: 200 when the database answers and the tick keeps up (jobs draining, deadlines on time, no DEAD jobs), 503 otherwise. `/v1/health` stays a dependency-free liveness check.
- Headers: `frame-ancestors 'none'`, `X-Frame-Options: DENY`, `base-uri`, `object-src`; `microphone=(self)` for voice input. `script-src` is still open: Privy and the Solana RPC load from origins that move with their SDKs, and a wrong value would break sign-in on a phone.
- `robots.txt`, `sitemap.xml` (ja and en) and `llms.txt` for agents.
- The server-side Claude reviewer is tuned for speed: effort low by default (`REVIEW_EFFORT`), 4k output, 25 s timeout with one retry. It takes effect once `ANTHROPIC_API_KEY` is set.
- README: eight MCP tools.

The owner's rule from this round: no rate limit on `/oauth/token`.

## Review within seconds, warnings, uptime (PR #20)

The outside AI review (01 §4.17) ran from a launchd timer every two minutes, so a submission waited a minute on average. `scripts/review-runner.ts --loop` now stays up and polls `/v1/admin/reviews` every 5 seconds (30 s back-off when the server is away), judges with `claude -p --effort low`, accepts `REVIEW_MODEL`, and logs the judging time. launchd uses `KeepAlive` instead of `StartInterval`. The Mac still has to be awake; `ANTHROPIC_API_KEY` on Vercel is the way to make the review independent of it.

Per 08 §5 the tick now counts DEAD jobs, payments in flight for over ten minutes and a low operator SOL balance, logs `tick_needs_operator`, and returns the counts. The GitHub Actions workflow `uptime` fetches `/v1/health/ready` every five minutes; a failed run emails the owner.
