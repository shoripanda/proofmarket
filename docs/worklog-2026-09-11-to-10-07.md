# Work log: 2026-09-11 → 2026-10-07

How ProofMarket went from a research repository to a live pilot, day by day. Written on 2026-10-09 from the commit history and the dated sections of the requirements (`specs/proofmarket/implementation/ja/01-requirements-definition.md` §4.8–§4.24). The later days are in `worklog-2026-10-08.md`.

## 2026-09-11 and 09-16: research

The repository started as `Solana-idea`, a place to test whether any real problem is better solved with Solana than with a normal database. Notes on the chain itself (`docs/solana-research-2026-09-11.md`), on the Colosseum hackathon playbook and on past winners (`docs/colosseum-hackathon-*.md`). The operating rules for AI agents working in the repo (`AGENTS.md`) date from here: ten questions every idea must survive before Solana is allowed in.

## 2026-10-02: the design, then the whole backend in one day

- Product definition: `docs/proofmarket-concept-2026-10-02.md` and `specs/proofmarket/` (requirements, API contract, privacy, acceptance criteria). The wedge: an AI agent asks a real person to check a fact about a public place and gets the answer back with proof.
- Implementation design in Japanese (the source of truth) and English: twelve documents from requirements to the deploy runbook (`specs/proofmarket/implementation/`), with a plan of fourteen PRs.
- Built the same day, PR-01 to PR-09: the monorepo skeleton; core domain logic (IDs, state transitions, task policy, evidence checks, consensus, evidence root); the requester API (API-key auth, idempotency, limits, create / get / cancel); the worker API (onboarding, tasks, claims, challenges, uploads, the evidence pipeline); the outbox job runner and the tick; the Anchor program's instruction handlers with LiteSVM tests.
- CI: typecheck, tests, the program, and a secrets scan (gitleaks). The failure ledger in `CLAUDE.md` began the same day.

## 2026-10-03: worker app, settlement on devnet, MCP over HTTP

- The Anchor settlement adapter and the devnet setup script (PR-10/11); signed webhooks, secret generation, the Supabase setup and the deploy runbook (PR-14).
- Worker screens W-01 to W-08 (login via Privy, onboarding, task list, task detail, capture, claims, payouts), the public result page, a local DEV_MODE on PGlite, Playwright end-to-end tests.
- MCP: the tools served over Streamable HTTP at `POST /mcp` with the API key, then OAuth 2.1 for phone AI apps (discovery metadata, dynamic registration, API-key consent, PKCE, rotation) so claude.ai and ChatGPT connectors can use it.
- Small things that mattered: the task list refreshes every 30 s with a "new" badge; Cloudflare quick tunnels for testing on a phone.

## 2026-10-04: the public site, ten feature extensions, AI review, x402

The owner asked for a public explanation site and ten extensions, "all of them, one at a time". Thirty-plus PRs, each merged on green CI.

- Site: top page with featured results, developers, workers, join, how-it-works with honest limits, pricing (cost formula, witness counts, refunds), a result walkthrough with an in-browser Solana check, rules and photo-removal requests, FAQ, draft terms / privacy / operator pages with enforced consent versions.
- Extensions B-01 to B-10: push notifications by coarse area; queue-length and storefront-notice task types; assurance levels fast / standard / high; recurring checks (`/v1/schedules`); reuse of a recent shared result; payout CSV and interest in yen payouts; explainable trust tiers; disputes that create a recheck; shops reporting "closed today" via a secret link; the requester console.
- 01 §4.15: the catalogue grew to 17 task types with number and text answers and optional location — "any hands-on work", not only "is the shop open".
- 01 §4.16–4.17: AI review of every submission against the request (Claude vision), and the arrangement that runs it on the operator's Mac through a Claude Code subscription instead of an API contract.
- 01 §4.18: up to four photos per submission. 01 §4.19: x402 — an agent with a Solana wallet pays in USDC and asks with no API key.
- Infrastructure: Supabase (17 migrations, RLS on every public table, a test that fails if a table lacks it), Privy, Vercel. The site went live at `proofmarket-rosy.vercel.app`.
- Public numbers at `/stats` and the pitch materials split into numbered folders (canvas, deck, video scripts, X posts, worker recruiting).

## 2026-10-05: work from home, proof links, the public map

- 01 §4.20: tasks that need no place (reading a document, a phone call) are listed and pushed to everyone.
- 01 §4.21: every result gets a public proof page and a badge — "a human checked this, when, by how many people" — for the agent to show its user.
- 01 §4.22: a public map of facts people checked, opt-in per request, 72 hours.
- The x402 demo agent sends any of the 17 types.

## 2026-10-06: watches, /try, the English site, the domain

- 01 §4.23: watches — keep checking until the answer you want comes back, with `stop_when` and `max_runs`; seven MCP tools in all.
- `/try`: play both sides of one request in the browser, no sign-up. `/en` and `/en/developers`: the English home and quick start.
- The domain moved to `proofmarket.fun` (runbook in `docs/domain-proofmarket-fun-2026-10-06.md`); the claude.ai connector was verified against production (`docs/agent-clients-check-2026-10-04.md`).
- A submission the outside reviewer never answers passes with a warning after 30 minutes, so a stopped Mac does not block workers.
- The report for the professor (`docs/submission/`, Japanese, with the production numbers as of that day).

## 2026-10-07: the open dataset, a lighter site, a repository of its own

- 01 §4.24: an open dataset of human-verified observations (`/data`, `/v1/public/dataset`, CC BY 4.0).
- The site got less text and more motion: a flow diagram, cards instead of JSON, five large header items, a tappable feel on everything. `/try` autoplays with the agent's reasoning typed out, and a second story (ten station elevators checked at once).
- The repository was split: `shoripanda/proofmarket` holds only ProofMarket (history rewritten with `git filter-repo`; the old research repo stays private). The README links the public repo and the demo video.
