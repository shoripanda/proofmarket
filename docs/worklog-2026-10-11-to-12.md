## SOL off chain (PR #28)

`AssetSchema = USDC | SOL` replaces six literals. Balances, reservations, payouts, the CSV and public stats are per asset (`paid_by_asset`); nothing adds the two together. `SOL_ENABLED` (off) gates acceptance; below 0.001 SOL is `VALIDATION_FAILED`. x402 stays USDC-only (`UNSUPPORTED_ASSET`, `x402_usdc_only`): its `exact` scheme is an SPL transfer.

## Program v1.2 (PR #29)

`AllowedMint` PDA (`["mint", mint]`) with `add_mint`/`remove_mint` (admin). `initialize_task` accepts the config mint or any allowed mint; the optional account is last and `allow-missing-optionals` keeps pre-1.2 clients working (main's adapter passed 3/3 against the new program). Settle and refund return the remainder to the operator's account of the task's mint.

The first design paid workers in wSOL and gave them an "unwrap" button. That cannot work: a fresh embedded wallet holds 0 SOL and cannot pay the unwrap fee. Settle now pays **native SOL** into the wallets: the vault is closed into the task account (a native token account closes with a balance), the program moves lamports to each recipient and returns the vault rent to the operator. Recipients below the rent-exempt minimum fail with `PayoutBelowRent`; the 0.001 SOL floor is above it. 23 program tests; localnet round trip with a wallet that had never existed. The Devnet program is **not yet upgraded**; the owner decides when (recommended: after the submission deadline).

## Self-service deposits (PR #30, migration 0028)

The requester gets one Solana Pay `reference` (an ed25519 public key) from the console and sends USDC or SOL to the operator wallet with it. Every tick polls up to 25 references, least recently checked first, with `getSignaturesForAddress(reference, until = last signature)`, reads only finalized transactions, sums system transfers to the wallet and `spl-token` transfers to the USDC account (inner instructions included), and writes one `deposits` row per signature plus the TOPUP in the same transaction. A transfer without the reference is not credited; the console says to send the operator the transaction ID. Verified on a local validator with real transfers. The migration was applied to Supabase before the merge; production shows the deposit section.
